# 정하민 홈페이지

자연어처리를 공부하는 학생의 개인 홈페이지입니다. [Astro](https://astro.build)로 만든 정적 사이트이고, 글과 프로젝트는 마크다운 파일로 씁니다.

- 사이트: https://roundycat.github.io
- 관리 화면: https://roundycat.github.io/admin/

## 실행하기

Node.js 22.23 이상(24 권장)이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 http://localhost:4321 을 열면 됩니다. 파일을 고치면 바로 반영됩니다.

## 글 쓰고 고치기 (관리 화면)

https://roundycat.github.io/admin/ 에서 글, 프로젝트, 첫 화면의 목록을 고칩니다. 컴퓨터와 휴대폰 브라우저에서 모두 열립니다.
[Sveltia CMS](https://sveltiacms.app) 를 쓰며, 저장하면 이 저장소에 커밋이 하나 생기고 몇 분 뒤 사이트에 반영됩니다. 중간에 거치는 서버는 없고, 브라우저가 GitHub 와 직접 통신합니다.

### 처음 한 번: 로그인

1. 관리 화면에서 **액세스 토큰으로 로그인**을 누르고, 안내에 있는 링크로 GitHub 의 토큰 만들기 화면을 엽니다.
2. Repository access 를 **Only select repositories** 로 바꾸고 `roundycat.github.io` 하나만 고릅니다.
3. Permissions 는 Contents: Read and write 하나면 됩니다. 만료일을 정하고 토큰을 만든 뒤 관리 화면에 붙여 넣습니다.
4. 휴대폰에서는 컴퓨터 관리 화면 오른쪽 위의 사람 모양 단추(계정 메뉴)에서 **모바일로 로그인**을 눌러 나오는 QR 코드를 찍으면 됩니다.

토큰은 그 브라우저에만 저장됩니다. 이 QR 코드와 토큰은 비밀번호처럼 다룹니다. 토큰이 있으면 누구나 이 저장소의 파일을 바꿀 수 있고, 바뀐 내용은 그대로 사이트에 올라갑니다. 내 기기가 아닌 곳에서 썼다면 계정 메뉴에서 **로그아웃**합니다. 만료되면 같은 방법으로 새로 만들고, 기기를 잃어버렸다면 GitHub 의 Settings > Developer settings > Personal access tokens 에서 지웁니다.

`https://roundycat.github.io` 로 시작하는 주소는 모두 같은 브라우저 저장 공간을 씁니다. 이 사이트나 이 계정의 다른 GitHub Pages 사이트(`roundycat.github.io/저장소이름/`)에서 실행되는 스크립트는 저장된 토큰을 읽을 수 있습니다. 방문자 통계나 댓글 위젯 같은 외부 스크립트를 넣게 되면, 그 전에 로그아웃하고 GitHub 에서 토큰을 지운 뒤 아래 「컴퓨터에서 고치기」의 방법으로 바꿉니다.

관리 화면에서 저장하면 커밋 작성자 이메일은 GitHub 가 계정 설정에 따라 적습니다. 처음 저장하기 전에 GitHub 의 Settings > Emails 에서 **Keep my email addresses private** 가 켜져 있는지 확인합니다. 꺼져 있으면 계정의 기본 이메일이 공개 저장소의 커밋에 남습니다.

### 메뉴

| 메뉴 | 고치는 것 | 저장되는 곳 |
| --- | --- | --- |
| 글 | 블로그 글 | `src/content/notes/*.md` |
| 프로젝트 | 프로젝트 목록과 상세 페이지 | `src/content/projects/*.md` |
| 첫 화면 > 소개와 연락처 | 첫 문단, 둘째 문단, 영어 소개, 사진, 연락처, CV | `src/data/profile.json` |
| 첫 화면 > 논문 및 발표, 수상, 활동, 소식, 읽고 있는 논문 | 첫 화면의 각 목록 | `src/data/*.json` |
| 에셋 (그림 모양 단추) | 글과 프로젝트에 넣을 그림 | `src/content/notes/images/` 등 |

사진과 CV 는 `public/uploads/` 에 올라가고 사이트에서 `/uploads/파일이름` 으로 열립니다. 칸에서 '제거'하거나 새 파일로 바꿔도 전에 올린 파일은 그대로 남아 같은 주소로 계속 열립니다. 내리려면 에셋의 「전역 에셋」에서 파일을 삭제합니다.

### 글 쓰기

1. **글 > 새로 만들기**(휴대폰에서는 연필 모양 단추)를 누르고 **Slug** 칸에 주소에 쓸 영문 이름을 적습니다. 컴퓨터에서는 화면 오른쪽에 이 칸이 열려 있고, 휴대폰에서는 저장 단추 옆 ⋮ 메뉴에서 **Slug** 를 누르면 나옵니다. `lora-rank` 라고 적으면 주소가 `/notes/lora-rank/` 가 됩니다. 비워 두면 저장되지 않고, 저장한 뒤에는 바꿀 수 없습니다. 프로젝트를 새로 만들 때도 같습니다.
2. 제목, 날짜, 한 줄 설명을 채우고 본문을 마크다운으로 씁니다.
3. 아직 공개하지 않을 글은 **초안**을 켜고 저장합니다. 초안은 사이트에 나오지 않지만, 저장소가 공개라서 GitHub 에서는 볼 수 있습니다. 한 번 저장한 글과 올린 파일은 나중에 지워도 저장소의 커밋 기록에 남습니다. 공개하면 안 되는 내용은 초안으로도 저장하지 않습니다.
4. 공개하려면 초안을 끄고 저장합니다. 첫 글이 올라가면 위쪽 메뉴와 첫 화면에 '글'이 생깁니다.

본문에서 쓰는 문법은 초안으로 넣어 둔 「글쓰기 문법 모음」에 모아 두었습니다. 필요 없으면 지워도 됩니다.

- 수식: `$W = W_0 + BA$` (문장 안), `$$ ... $$` (따로 한 줄). 관리 화면의 미리 보기에서는 수식이 원문 그대로 보이고, 사이트에서만 수식으로 그려집니다. 금액의 달러 기호는 `\$5` 처럼 역슬래시를 붙여 씁니다.
- 코드: 세 개의 백틱(```) 뒤에 `python` 처럼 언어 이름을 적습니다.
- 그림: 화면 위쪽의 그림 모양 단추(에셋, 휴대폰에서는 아래쪽 가운데)를 눌러 「글」 폴더에 먼저 올리고, 거기 보이는 파일 이름 그대로 `![그림 설명](./images/파일이름.png)` 이라고 적습니다. 미리 보기에 그림이 보이면 경로가 맞는 것입니다. 휴대폰 사진(JPEG, HEIC)은 올릴 때 WebP 로 바뀌면서 크기가 줄고 위치 정보가 지워집니다. 올린 뒤 파일 이름이 `.webp` 로 끝나는지 확인합니다.

### 글 지우기

지울 글을 열고 저장 단추 옆 ⋮ 메뉴에서 **삭제**를 누릅니다. 글에 넣었던 그림은 같이 지워지지 않으므로 에셋의 「글」 폴더에서 따로 지웁니다. 지운 글과 그림도 GitHub 의 커밋 기록에는 남습니다.

### 저장했는데 사이트가 바뀌지 않을 때

저장소의 [Actions 탭](https://github.com/roundycat/roundycat.github.io/actions)을 봅니다. 빨간 표시가 있으면 방금 저장한 내용에 문제가 있어서 배포가 멈춘 것이고, 사이트는 직전 상태 그대로 남아 있습니다. 표시를 눌러 들어가면 어느 파일의 어느 칸이 문제인지 나옵니다. 흔한 원인은 다음과 같습니다.

- 본문에 적은 그림 파일 이름이 올린 이름과 다름. 이때 오류에는 글 이름 없이 그림 경로(`./images/...`)만 영어로 나옵니다.
- 주소 칸에 `https://` 없이 `github.com/...` 처럼 적음
- 첫 문단이나 소식에서 없는 페이지로 링크함 (지운 글, 초안인 글 포함)
- 첫 문단의 형광펜 표기가 틀림

### 첫 문단 표기법

첫 화면 > 소개와 연락처의 첫 문단에서 두 가지 표시를 쓸 수 있습니다.

```text
[정하민]{PS}입니다. [연세대학교]{OG} 소프트웨어학부에서 ...
한의사 국가시험으로 언어 모델을 평가하는 [벤치마크](/projects/meridian/) 논문을 ...
```

- `[글자]{PS}`, `[글자]{OG}`: 개체명 인식 도구처럼 형광펜과 태그를 붙입니다. 태그는 KLUE 개체명 태그(PS 인명, OG 기관)를 따릅니다. 조사는 괄호 밖에 두세요.
- `[글자](/주소/)`: 링크입니다.

### 화면에 나오는 규칙

- 비어 있는 목록(글, 소식, 읽고 있는 논문)은 섹션째 숨겨집니다. 글이 하나도 없으면 위쪽 메뉴의 '글'도 숨겨집니다.
- 첫 화면에는 최신 글 5개가 나오고, 전체는 `/notes/` 에 있습니다. 글 목록은 `/rss.xml` 로도 받아 볼 수 있습니다.
- 수상, 활동, 논문은 관리 화면에 놓인 순서대로 나옵니다.
- 소식은 사이트를 마지막으로 갱신한 때를 기준으로 최근 12개월 안의 것만 4개까지 나옵니다.
- 초안인 글과 프로젝트는 사이트를 만들 때 읽지 않습니다. 그래서 초안으로 링크하면 없는 페이지로 링크한 것이 됩니다.

## 컴퓨터에서 고치기

관리 화면 없이 파일을 직접 고쳐도 됩니다. 글과 프로젝트는 마크다운 파일, 첫 화면의 정보는 `src/data` 의 JSON 파일입니다.
관리 화면에서 저장한 내용은 GitHub 에만 있으므로, 컴퓨터에서 고치기 전에 `git pull` 을 먼저 합니다.

| 바꾸고 싶은 것 | 파일 |
| --- | --- |
| 글 | `src/content/notes/*.md` (파일 이름이 주소) |
| 프로젝트 | `src/content/projects/*.md` (파일 이름이 주소) |
| 소개, 연락처, 논문, 수상, 활동, 소식 | `src/data/*.json` |
| 이름 | `src/data/site.ts` |
| 관리 화면의 입력 칸 | `public/admin/config.yml` |
| 색, 글꼴 크기 | `src/styles/global.css` 맨 위 `:root` |

글 파일의 머리말은 이렇게 생겼습니다.

```markdown
---
title: 글 제목
date: 2026-11-02
description: 글 목록과 검색 결과에 보일 한 문장
draft: false
---
```

`npm run dev` 를 켜 두면 초안도 보이고 수식도 그려지므로, 수식이 많은 글은 공개하기 전에 http://localhost:4321 에서 확인할 수 있습니다.
Chrome 에서 http://localhost:4321/admin/index.html 을 열고 **로컬 저장소로 작업**을 고르면, 로그인 없이 이 폴더의 파일을 관리 화면으로 고칠 수 있습니다. 이때는 커밋과 push 를 직접 해야 사이트에 올라갑니다.
그림 파일을 폴더에 직접 넣으면 그대로 저장소에 올라갑니다. 휴대폰 사진은 위치 정보가 지워지지 않으므로 관리 화면으로 올립니다.

### 형식 검사

글과 프로젝트의 머리말, `src/data` 의 JSON 은 빌드할 때 형식을 검사합니다(`src/content.config.ts`, `src/data/schema.ts`). 형식이 틀리면 빌드가 멈추고 사이트는 바뀌지 않습니다.

자리만 잡아 둘 항목에 `example: true` 를 붙이면 개발 서버에서 점선으로 된 `예시` 표시가 보이고, 그 항목이 남아 있는 동안 `npm run build` 가 멈춥니다. 없는 경력이나 지어낸 숫자가 실수로 배포되지 않게 하려는 장치입니다.

### 관리 화면 버전 올리기

`public/admin/index.html` 은 Sveltia CMS 본체 스크립트의 버전과 해시를 고정해 둡니다. 새 버전으로 바꾸는 방법은 그 파일 안에 적혀 있습니다.

## 배포하기 (GitHub Pages)

1. GitHub 에 `<아이디>.github.io` 라는 이름으로 새 저장소를 만듭니다.
2. `astro.config.mjs` 맨 위의 `const site` 를 `'https://<아이디>.github.io'` 로 바꿉니다.
   (example.github.io 로 남아 있으면 빌드가 멈춥니다.)
   저장소 이름이 `<아이디>.github.io` 가 아니라면 `const base` 에 `'/<저장소 이름>'` 을 적습니다.
   `public/admin/config.yml` 의 `repo` 와 `site_url` 도 새 저장소에 맞게 바꿉니다.
3. 이 폴더를 그 저장소에 push 합니다.
   ```bash
   git init
   git add .
   git commit -m "첫 배포"
   git branch -M main
   git remote add origin https://github.com/<아이디>/<아이디>.github.io.git
   git push -u origin main
   ```
4. 저장소 Settings > Pages > Build and deployment > Source 를 **GitHub Actions** 로 바꿉니다.

그다음부터는 main 에 push 할 때마다(관리 화면에서 저장할 때 포함) `.github/workflows/deploy.yml` 이 자동으로 빌드하고 배포합니다.
페이지 아래 '마지막 수정' 날짜는 마지막 커밋 날짜를 한국 시간으로 씁니다.

## 명령어

| 명령어 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 (http://localhost:4321) |
| `npm run build` | `dist/` 에 배포용 파일 만들기 (예시가 남아 있으면 멈춤) |
| `ALLOW_EXAMPLES=1 npm run build` | 예시가 남아 있어도 빌드 |
| `npm run preview` | 만든 배포용 파일을 로컬에서 미리 보기 |
